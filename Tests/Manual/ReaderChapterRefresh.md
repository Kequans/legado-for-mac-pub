# 阅读器章节缓存刷新

## 正常刷新

1. 在“设置 → 阅读缓存”确认预加载章节数为 `N`，并打开一本使用在线书源的书。
2. 等待当前章节和后续章节完成预加载，确认控制台出现“章节已缓存，跳过”一类缓存日志。
3. 点击正文显示阅读工具栏，点击右上角的刷新按钮。
4. 刷新期间按钮显示进度指示。控制台应显示手动刷新开始日志，并逐章显示刷新结果；本章之后刷新 `N` 章，已缓存章节也应重新请求。
5. 刷新结束后切换到后续章节，确认章节正文可正常读取。
6. 关闭并重新打开该书，确认更新后的正文可从缓存读取。

## 网络失败时

1. 对已经缓存的章节点击刷新后，让书源请求失败。
2. 确认当前章节显示刷新错误，且控制台记录失败章节。
3. 再次打开该章节时，应重新请求网络，不应继续使用刚被刷新操作清除的旧缓存。

## 边界检查

- 将“预加载章节数”设为最小值和最大值，刷新时分别确认后续请求数量与设置一致。
- 在书的最后一章刷新，确认只请求当前章及实际存在的后续章节。
- 本地导入书籍不显示在线章节刷新按钮。

## 并发与导航回归（2026-10-22）

- 使用慢响应书源，连续切换 A → B → A，令较早请求最后返回：正文和错误信息必须属于最后一次选中的章节。
- 当前章网络请求尚未返回时点击刷新：旧请求不得覆盖刷新结果，也不得重新启动普通预加载。
- 刷新后续章节期间跳转章节：跳转立即生效，旧刷新停止后续请求，晚返回的数据不得写入。
- 刷新或预加载期间换源：旧书源响应不得覆盖新正文，不得以新 bookUrl 保存旧章节。
- 刷新期间关闭阅读窗口：当前请求晚返回后不得继续写缓存或请求剩余章节。
- 普通预加载期间切章：新任务从新章节开始，章节范围固定，不能随着导航跳跃而漏章。
